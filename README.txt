============================================================
 עדכון — תזרים מזומנים חודשי + הסרת גישת פרופיל משני האייקונים
 (בנוסף לעדכון הקודם: תפריט צד, קיצור דרך לחובות, תובנות והערות)
============================================================

קבצים בזיפ:
1. index.html    — שונה
2. style.css     — שונה
3. script.js     — ללא שינוי (מצורף ליישור גרסאות)
4. debts.js      — ללא שינוי (מצורף ליישור גרסאות)
5. notes.js      — ללא שינוי (מהעדכון הקודם)
6. sidemenu.js   — שונה (פריט "תזרים חודשי" הפך מ"בקרוב" לפעיל)
7. cashflow.js   — קובץ חדש! (כל הלוגיקה של מסך התזרים החודשי)
8. export-patch.js — קובץ חדש! (משדרג את ייצוא ה-Excel הראשי)
9. import-patch.js — קובץ חדש! (משדרג את טעינת ה-Excel הראשית — תיקון 2 באגים)

קבצים שלא נכללים כאן ואינם צריכים שינוי:
patch.js, glide.js, pension-profile-fix.js, dashboard-v8.js,
dashboard-upgrade.css, service-worker.js, manifest.json

התקנה
============================================================
1. החלף בריפו: index.html, style.css, sidemenu.js
   (וגם script.js, debts.js, notes.js אם נוח לך — הם זהים
   בפועל לגרסה הקודמת שהעלית).
2. הוסף שלושה קבצים חדשים לתיקיית הפרויקט: cashflow.js,
   export-patch.js ו-import-patch.js
3. מומלץ לעדכן את מספר הגרסה ב-service-worker.js
   (CACHE_NAME, למשל ל-v43) כדי לוודא טעינת הגרסה החדשה.

============================================================
מה נוסף / השתנה בעדכון הזה
============================================================

1. מסך חדש: "תזרים חודשי" (cashflow.js)
   -----------------------------------------------------
   נגיש מהתפריט הראשי (פריט 10, לפי ההכנה שכבר בוצעה) —
   הפריט הפך מ"בקרוב" למסך פעיל לגמרי.

   מבנה הנתונים (plan.cashflow):
   -----------------------------
       plan.cashflow.months["2026-08"] = {
           income:          [ {id, name, planned, actual, linked} ],
           variable:        [ ... ],   // הוצאות משתנות
           semiFixed:       [ ... ],   // הוצאות קבועות-משתנות
           fixed:           [ ... ],   // הוצאות קבועות
           nonCashSavings:  [ ... ]    // הוצאות לא תזרימיות/הפקדות
       }
   מפתח החודש הוא מחרוזת "YYYY-MM", כך שניתן להשוות ולמיין
   חודשים בהשוואת מחרוזות פשוטה — זה גם הבסיס לפיצ'ר
   "טען מבנה מחודש קודם" ולשמירת היסטוריה חודשית מלאה
   (כל חודש נשמר בנפרד בתוך התוכנית הפעילה, לצד שאר
   הנתונים, ומיוצא/מסונכרן באותו אופן).

   כל שורה היא אובייקט { id, name, planned, actual, linked }.
   השדה "linked" מכיל מפתח יציב (למשל "debt:2" או "inv:0")
   כאשר השורה יובאה אוטומטית מ-plan.debts[] או
   plan.investments[] — כך מנגנון הסנכרון (סעיף 3 למטה)
   יודע להימנע מהזנה כפולה של אותו סעיף.

   פונקציונליות:
   • 4 קטגוריות הוצאה + קטגוריית הכנסות, כל אחת בלשונית
     (Tab) נפרדת: הכנסות | הוצאות משתנות | הוצאות
     קבועות-משתנות | הוצאות קבועות | הוצאות לא תזרימיות/
     הפקדות.
   • בכל שורה: עמודת "צפי", עמודת "פועל" ועמודת "הפרש"
     עם הדגשה ויזואלית — ירוק כשהביצוע טוב מהתכנון (הכנסה
     גבוהה/שווה לצפי, או הוצאה נמוכה/שווה לצפי), אדום
     כשיש חריגה. שורה שטרם הוזן בה "פועל" מוצגת עם קו
     מפריד ניטרלי (—) במקום צבע מטעה.
   • כרטיס "תזרים פנוי לחיסכון" גדול ובולט למעלה — מחשב
     דינמית סה״כ הכנסות (בפועל) פחות סך כל ההוצאות בכל
     4 הקטגוריות (בפועל), עם צבע ירוק/אדום לפי הסימן,
     ומציג גם את הצפי לצדו.
   • הוספה, עריכה ומחיקה של סעיפים בזמן אמת בכל קטגוריה.
   • מעבר בין חודשים בחיצים ‹ › או בבורר חודש (input type
     month), עם שמירת היסטוריה מלאה של כל חודש בנפרד.

2. טעינת נתונים מחודש קודם
   -----------------------------------------------------
   כפתור "טען מבנה מחודש קודם" מאתר את החודש הקודם הקרוב
   ביותר שיש בו נתונים, ומשכפל את כל השורות עם הסכומים
   ה"צפי" שלהן (שדה "פועל" מתאפס ל-0 בחודש החדש). אם כבר
   קיימים נתונים בחודש הנוכחי, המערכת מבקשת אישור לפני
   החלפתם.

3. סנכרון מסעיפים פיננסיים קבועים (מניעת כפילויות)
   -----------------------------------------------------
   כפתור "סנכרן מסעיפים קבועים" מושך אוטומטית:
   • כל הלוואה מטאב "החובות שלנו" (עם תשלום חודשי) →
     נכנסת ל"הוצאות קבועות" עם סכום "צפי" = התשלום החודשי.
   • כל מסלול השקעה (שאינו פנסיה) עם הפקדה חודשית → נכנס
     ל"הוצאות לא תזרימיות / הפקדות".
   סעיף שכבר יובא בעבר (מזוהה לפי מפתח linked) לא יובא
   שוב בהרצה חוזרת — כך אפשר ללחוץ על הכפתור בכל חודש בלי
   לדאוג לכפילויות. סעיפים חדשים בלבד יתווספו.

4. ייצוא דוחות
   -----------------------------------------------------
   • "ייצוא HTML" — פותח דוח מעוצב וממותג (כמו דוח
     ההשקעות הקיים באפליקציה) בטאב חדש, עם כפתור הדפסה/
     שמירה כ-PDF. כולל את כל הטבלאות + כרטיס הסיכום.
   • "ייצוא Excel" — מייצא קובץ xlsx עם גיליון סיכום
     וגיליון נפרד לכל קטגוריה (בשימוש בספריית ה-SheetJS
     שכבר טעונה באפליקציה עבור ייצוא/ייבוא קיימים).

5. הסרת גישה לפרופיל משני האייקונים בראש דף הבית
   -----------------------------------------------------
   כפי שביקשת: כפתור הפרופיל (אייקון אדם) שהיה ליד כפתור
   התפריט למעלה הוסר לגמרי מדף הבית. כרטיס "שווי נקי
   מומלץ" (המוצג רק כשיש נתוני גיל והכנסה) הפך לכרטיס
   תצוגה בלבד — אינו לחיץ יותר ואינו מוביל לפרופיל.
   הגישה למסך "פרופיל משפחתי" זמינה כעת אך ורק דרך פריט 1
   בתפריט הצד (☰).

6. שדרוג ייצוא ה-Excel הראשי (export-patch.js)
   -----------------------------------------------------
   כפתור "הורדת נתונים" בדף הבית (exportExcel המקורי
   ב-script.js) ייצא עד כה רק 6 גיליונות: מסלולי השקעה,
   פרופיל, יעד פרישה, יעד הון, יעדי חיים ומפת דרכים —
   ולא כלל את הנתונים שנוספו בעדכונים האחרונים. הקובץ
   החדש export-patch.js מחליף את הפונקציה הגלובלית
   (window.exportExcel) בגרסה מורחבת שמוסיפה:
   • שדה "הכנסה משפחתית חודשית נטו" לגיליון הפרופיל.
   • גיליון חדש "החובות שלנו" — כל ההלוואות עם סכום,
     ריבית, תשלום חודשי ומועד סיום.
   • גיליון חדש "תובנות והערות" — כל ההערות עם תאריך
     כתיבה ותאריך עדכון אחרון.
   שים לב: מדובר בהחלפה מלאה (לא "עטיפה") של הפונקציה,
   כי exportExcel המקורי בונה את קובץ ה-Excel ושומר אותו
   באותה פעולה סינכרונית אחת, בלי נקודת "האזנה" שממנה
   ניתן להוסיף גיליונות לפני השמירה. שאר 6 הגיליונות
   המקוריים שוכפלו ללא שינוי כדי לשמר את ההתנהגות הקיימת
   במדויק. הכפתור הקיים "הורדת נתונים" ימשיך לעבוד בדיוק
   כפי שהוא, רק עם תוצאה מלאה יותר — לא נדרש שום שינוי
   נוסף ב-index.html מעבר לטעינת הקובץ.

7. תיקון 2 באגים בטעינת קובץ (import-patch.js)
   -----------------------------------------------------
   דיווחת ששני דברים לא נטענו בחזרה מקובץ שיוצא-וטוען:
   1. נתוני "החובות שלנו" — לא יובאו בכלל בחזרה.
   2. "הכנסה משפחתית חודשית" מהפרופיל — לא יובאה בחזרה.

   הסיבה: בדיוק כמו exportExcel, גם importExcel המקורי
   ב-script.js נכתב לפני שנוספו תכונות אלה, ולכן לא ידע
   לקרוא את הגיליונות/השדות החדשים. תיקנתי באותו אופן —
   קובץ import-patch.js מחליף לגמרי את הפונקציה הגלובלית
   (window.importExcel) בגרסה מורחבת שמוסיפה:
   • קריאת השדה "הכנסה משפחתית חודשית נטו (₪)" מגיליון
     הפרופיל בחזרה אל profile.monthlyIncome.
   • קריאת גיליון "החובות שלנו" בחזרה אל plan.debts[]
     (כולל שחזור נכון של סוג הלוואה מותאם-אישית, אם היה).
   • כבונוס: קריאת גיליון "תובנות והערות" בחזרה אל
     plan.notes[] (אותו באג בדיוק היה קיים גם שם, גם אם
     לא דיווחת עליו) — כולל שחזור תאריך הכתיבה/עדכון.
   שאר הגיליונות (השקעות, יעדים, מפת דרכים) יובאים בדיוק
   כמו קודם, ללא שינוי בהתנהגות. לאחר הטעינה, המסכים
   הרלוונטיים (חובות, פרופיל, תובנות, ולוח הבית) מתעדכנים
   אוטומטית כדי שהנתונים החדשים יופיעו מיד בלי צורך
   ברענון ידני.

למה לא React
============================================================
האפליקציה כולה בנויה כקובץ index.html יחיד + קבצי JS
ב-vanilla JS תואם ES5, נטענת ב-GitHub Pages וללא כלי בנייה
(build tools) — כך שניתן לערוך ולפרוס אותה ישירות מהאייפון.
הוספת React הייתה מחייבת ספריית build (webpack/vite) או
תלות ב-CDN עם JSX-transpiling בזמן ריצה (Babel standalone),
מה שמסבך את זרימת העבודה שלך ופוגע בביצועים. לכן מימשתי את
מסך התזרים באותו סגנון בדיוק כמו debts.js ו-notes.js —
מודול עצמאי הנטען אחרי script.js, ללא כל תלות חיצונית
נוספת. אם בעתיד תרצה לעבור לארכיטקטורת React (עם build
step), זה אפשרי אך ידרוש שינוי בתהליך הפיתוח/פריסה כולו.

הערות טכניות
============================================================
• כל הלוגיקה החדשה נמצאת בקובץ נפרד (cashflow.js), ללא
  נגיעה בקבצי הליבה — בהתאם לארכיטקטורה הקיימת.
• נכתב בסגנון ES5 תואם iOS Safari (ללא const/let/arrow
  functions/template literals), כמו שאר קבצי הפרויקט.
• עבר בדיקת תחביר (node --check) ותקין.
• לא נמצאו התנגשויות id בין index.html לקבצי ה-JS.
• עוצב לפי שפת העיצוב הקיימת (Heebo, טוקני הצבע והרדיוסים
  הגלובליים ב-style.css) כך שהמסך ייראה חלק מהמערכת.
